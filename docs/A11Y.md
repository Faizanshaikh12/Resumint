## 2. Manual Keyboard & Assistive Technology Checklist

All core workflows have been verified using keyboard navigation without mouse input:

### 2.1 Navigation & Tab Order
- [x] **Skip Link:** A high-contrast skip link (`#main-content`) is available at the top of the DOM and becomes visible on first tab press.
- [x] **Logical Tab Flow:** Focus follows a natural reading order: Header Logo -> Navigation Links -> Main Actions -> Forms -> Footer.
- [x] **Focus Ring Visibility:** High-visibility focus rings (`focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`) are present on all interactive elements: buttons, links, inputs, selects, tabs, and radio cards.
- [x] **Keyboard Trapping in Modals:** Radix/shadcn Dialog primitives actively trap focus within the active dialog and restore focus to the triggering element upon closure (`Escape` or cancel).

### 2.2 Drag Handles & Icon-Only Buttons
- [x] **Drag Handles:** Section reordering handles include descriptive `aria-label="Reorder [Section Name] section"` and support keyboard reordering via arrow keys (`aria-roledescription="sortable"`).
- [x] **Icon Buttons:** All icon-only buttons (e.g. undo, redo, delete, duplicate, share, copy link, collapse, external links) possess explicit `aria-label` or `title` attributes.
- [x] **Decorative Icons:** Purely decorative Lucide icons are marked with `aria-hidden="true"`.

### 2.3 Responsive Reflow & Zoom
- [x] **320px Viewport:** Validated at 320x568 (iPhone SE minimum). No horizontal overflow occurs, navigation collapses into accessible mobile stacks, and the live preview switches to responsive tabs.
- [x] **200% Zoom:** Content reflows seamlessly at 200% browser zoom without text clipping, overlapping containers, or broken button targets.
- [x] **Touch Targets:** Interactive targets satisfy the WCAG 2.2 Target Size (Minimum) criterion: all buttons and tap areas are at least 24x24px, with primary action buttons sized at 36-48px for comfortable mobile use.

### 2.4 Motion & Animation
- [x] **Reduced Motion:** All micro-animations, spinners, and accordion transitions respect `@media (prefers-reduced-motion: reduce)` via Tailwind's motion utilities, eliminating sudden layout shifts for motion-sensitive users.

## 4. Semantic Hierarchy & ATS Parsing Guarantee
Every resume template is rendered as pure, un-nested semantic HTML:
- Exactly one `<h1>` per document containing the candidate's name.
- Section titles are structured with `<h2>` tags.
- Individual job positions and degrees use semantic `<article>` tags with `<h3>` titles.
- Contact items and skills are rendered as semantic unordered lists (`<ul>`, `<li>`).
- Zero reliance on HTML tables, fixed absolute positioning, or multi-column layout floats that confuse automated screen readers and applicant tracking algorithms.
